# 视频转白膜（Video to Blockout）初步计划

> 状态：调研阶段，未开工。
> 本文件记录可行性判断、技术路线和分工，供日后决定是否立项。

---

## 一、目标（对齐需求原文）

需求来自「白模表达规范」，核心结论如下：

> "几何体可以简化，但空间关系不能随意简化。"

白模需使用 Blender 3D 软件制作，用尽可能简单的 3D 几何体，表达真实视频中的：

- 人物
- 物体
- 场景空间
- 运动轨迹
- 相机运动
- 遮挡关系
- 光源位置

**精度要求**：白模不要求达到最终资产精度，但**投影出来的位置必须与原片对齐**，且需保留足够的场景、主体、动作及相机信息，使其可以作为最终视频的结构参考。

**翻译成工程语言**：

1. 相机内参 + 外参要准（位姿、焦距）
2. 每个主体在每一帧的三维位置要准
3. 遮挡关系要正确 —— 被挡住的部分也得推断出来
4. 绝对尺度要合理

---

## 二、可行性结论

### 能做到的

**AI 出初稿 + Blender 里半自动修 + 人工兜底。** 这个组合现在就能做，效果看素材质量。

### 做不到的

**一键全自动产出可直接当结构参考的白膜。** 即使勉强跑出来，误差也得人修。

### 为什么做不到

难点不在 Blender，在「从像素恢复三维空间」。

- **遮挡推断**：单目重建里，被挡住的部分没有像素证据，只能靠模型猜。这是研究前沿问题，不是工程问题
- **绝对尺度**：单目视频没有真实尺度信息，只能靠追踪点云归一，误差累积
- **相机**：抖片、大运动、变焦会破坏特征匹配

---

## 三、关于接入 DeepSeek API 的判断

**结论：接 API 解决不了核心问题。**

### DeepSeek 公开 API 的能力边界

- 是**文本模型**，没有视频输入，也没有图像输入
- 输出是文字和代码，生成不了三维坐标、相机位姿、深度图、骨骼关键帧

### 它能干什么

| 用途 | 说明 |
|---|---|
| 写 Blender 插件代码 | 主力用途 |
| 写外部管线脚本 | 串模型、处理数据 |
| 看报错改 bug | 调试辅助 |
| 生成文档流程 | 说明与规范 |
| 当调度员 | 决定哪段画面走哪套策略 |

**一句话：它让你写代码更快，不让视频变白膜变可能。**

### 唯一能真正接上的一处

用自然语言指挥 Blender 摆场景（如"把这个盒子往左挪 20 厘米再转 30 度"），DeepSeek 生成 `bpy` 脚本直接跑。

**但前提是场景里已经有几何体了。它挪得动东西，变不出东西。**

## 四、技术架构

分两层：Blender 外做重建，Blender 内做装配。

### 4.1 外部重建管线（Python + 视觉模型）

全部开源免费，跑本机或租 GPU。

| 环节 | 候选方案 | 产出 |
|---|---|---|
| 相机求解 | COLMAP / GLOMAP / Blender 自带追踪 | 相机位姿 + 焦距 |
| 单目深度 | Depth Anything V2 / UniDepth / Metric3D | 每帧深度图 |
| 视频分割 | SAM 2 | 视频级 mask 序列 |
| 人体姿态 | GVHMR / TRAM / 4D-Humans | 每帧 SMPL 参数 → 骨骼动画 |
| 物体 | mask + 深度 + 点云 | 包围盒/圆柱，逐帧关键帧 |
| 背景 | 平面/盒子拼装，或保留点云 | 场景代理几何 |

**备注**：Blender 自带运动追踪能解相机轨迹和焦距，但抖片或大运动建议用 COLMAP / GLOMAP。

### 4.2 Blender 插件（装配车间）

插件本身用 **Python + `bpy`** 编写，是这份计划里最确定能交付的部分。

功能清单：

1. 导入重建数据（相机、深度、mask、SMPL）
2. **代理几何自动生成器** —— 框 / 柱 / 球三件套
3. 相机动画烘焙
4. 白模材质预设（纯灰 + AO / MatCap）
5. **原片投影叠层** —— 半透明对比
6. **对齐打分** —— 自动算偏差并标红
7. 手动推拉、替换几何

> **第 5、6 条是最值钱的。** 需求原文说"投影出来的位置必须与原片对齐"，这说明存在一个可自动打分的验收标准，能省掉大量人眼比对。

## 五、降低难度的关键变量

### 5.1 素材拍摄方式（影响最大）

| 素材 | 难度 | 说明 |
|---|---|---|
| iPhone（LiDAR 或双摄） | 低 | 直接拿 RGBD，绝对尺度、深度都有。比纯单目好一个量级 |
| 固定机位单目 | 中 | 相机基本不用解，主要解深度和主体 |
| 手持运动单目 | 高 | 相机、深度、遮挡全都要解，误差累积 |

### 5.2 待确认的问题

决定管线选型前，需要先答：

- [ ] 素材是什么设备拍的？
- [ ] 固定机位还是手持运动？
- [ ] 主体以人物为主，还是场景为主？
- [ ] 单条视频时长 / 分辨率？
- [ ] 白模给谁用（内部参考 / 交付客户）？

## 八、若立项的下一步

1. 回答问题清单（第 5.2 节）
2. 拿一条真实素材跑通 COLMAP，验证相机可解
3. 跑一次 Depth Anything V2，看深度质量
4. 用 Blender 手工搭一版最简白模，验证「投影对齐」这条验收标准能量化
5. 上面四步都成立，再谈写插件

> **建议**：先花一两天做第 2–4 步的验证，比直接开写插件划算。如果素材本身解不出来，代码写多少都没用。

## 九、结论

- Blender 插件：**能写，确定性高**
- 视频自动转白膜：**能做出初稿，做不出免修成品**
- 接 DeepSeek API：**对核心难点无帮助，只加速开发**
- 是否值得做：取决于素材类型和精度容忍度
