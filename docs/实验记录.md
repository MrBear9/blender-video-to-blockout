## 一、能成的：TUM 室内桌面

**数据**：TUM RGB-D `freiburg1_desk`，办公室桌面，40 帧

**结果**：
```
注册帧数:        40/40
三维点:          2534 → 2382（去离群）
相机位姿误差:    1.86 厘米（对 groundtruth）
轨迹长度:        8.95 米
相对误差:        0.21%
```

**为什么成**：桌面上有大量静态可追踪物体（键盘、显示器、书本、线缆），
SIFT 特征充足且跨帧稳定。

**白模效果**：能框出显示器、键盘、桌面，位置对得上。

## 二、没成的：人物舞蹈

### 试过四种素材

| 素材 | 结果 | 原因 |
|---|---|---|
| Pexels 航拍海浪 | 无特征 | 水面一直在动 |
| Pexels 瀑布固定机位 | 解不出 | 相机没动，无基线，三角化不出来 |
| Pexels 人物特写 | 未试 | 背景虚化，人物在动 |
| AIST 单机位移动相机 | 解不出 | 纯旋转无平移，全是退化配置 |

### AIST 单机位详细结果

```
特征点:  811 ~ 1629 / 帧（不算少）
匹配数:  333 ~ 1056 / 对（很正常）
几何验证: config=6（退化）×736, config=3（单应）×44
          → 没有一对解出本质矩阵
```

`config=6` 意思是「纯旋转或无平移」。相机在转，但没有位移，
所以视差为零，三角化不出任何三维点。

### AIST 三机位详细结果

```
注册帧:  72/72
三维点:  1015 → 675
```

**但几何不对**：

```
cam0 与 cam1 相距  0.44
cam0 与 cam2 相距 11.81
cam1 与 cam2 相距 12.15
```

三个机位应该环绕舞者，实际两个挤在一起、一个在对角。

**根因**：

1. **白墙没有纹理** —— 唯一可追踪的是舞者本人，而舞者在动
2. **c03/c05/c07 编号不保证等距环绕** —— 实际几何分布很差
3. **没有重力先验** —— COLMAP 不知道哪边是上

**表现**：白模盒子偏在画面一侧，换机位后完全看不见。

## 三、从这些失败里学到了什么

### 1. 相机不动 = 解不出来

不管画面多丰富，**相机必须有平移**。
纯旋转（站在原地环拍）在数学上就是退化情形。

### 2. 能追踪的必须是静态的

人物舞蹈的难题：**主体在动，能追踪的只剩背景**。
如果背景是白墙，就等于没背景。

### 3. 多机位要真的分布开

三个相机挤在一起，等于一个相机。
真正的多机位需要均匀环绕（AIST 的 c01~c09 里要挑分布好的）。

### 4. 坐标系没有重力

COLMAP 输出是任意右手系。要靠人工或额外信息定"上"。

## 四、如果要继续做人物白模

两条路：

### A. 换素材

找**有纹理的环境 + 人物**。街头、陈设丰富的室内。

这样背景能提供大量稳定点，相机能解出来，人再从点云里框。

### B. 换方法：不做全场重建，只做人

不用 COLMAP 解相机，改成：

1. 每个机位单独做人形检测（YOLO / MediaPipe）
2. 得到每帧的二维框
3. 三个机位的二维框做三维三角化
4. 输出每帧的三维包围盒

**这条路不需要场景纹理**，因为不依赖特征点匹配。
但需要：
- 机位之间标定过（或者手工标定）
- 时间同步
- 人形检测模型

AIST 这批数据**本来就提供了相机参数**（AIST++ 项目有 `setting*.json`），
如果直接用那个标定，就不用跑 COLMAP 了。
